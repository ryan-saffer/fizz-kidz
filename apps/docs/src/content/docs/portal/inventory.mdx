Inventory tracks consumable stock used by studios. It has three connected parts: the catalogue, a generated shopping
list, and usage rules.

<CardGrid>
  <Card title="Inventory" icon="document">
    The shared item catalogue plus the selected studio's current quantity or level.
  </Card>
  <Card title="Shopping list" icon="list-format">
    A calculation based on upcoming in-studio party bookings, active usage rules, current counts, and minimum targets.
  </Card>
  <Card title="Usage rules" icon="puzzle">
    Defines how much of an item a base party, food package, or addition needs per booking, per child, or both.
  </Card>
</CardGrid>

What you can view or edit depends on your Portal responsibilities. The master organisation can choose a studio for stock
and can generate a shopping list grouped across studios.

## Keep stock current

<Steps>
  <ol>
    <li>Confirm the studio shown in the catalogue.</li>
    <li>Find the item using search, category, or stock-status filters.</li>
    <li>
      For quantity items, use <strong>Receive</strong> to add stock or <strong>Set stock</strong> after a count.{' '}
      <strong>Receive</strong> is hidden while the count is unknown, so set the stock first.
    </li>
    <li>
      For level-based items, use <strong>Update level</strong> to choose the current level.
    </li>
    <li>
      Use the <strong>…</strong> menu for <strong>Mark count unknown</strong> when a count can no longer be trusted, or{' '}
      <strong>Mark unused here</strong> when that studio does not track the item. Don't mark an item unused when it is
      only temporarily out of stock.
    </li>
    <li>
      To start tracking an unused item again, select <strong>Track here</strong>.
    </li>
  </ol>
</Steps>

Quantity items hold a numeric count. Level-based items use values such as high, medium, low, out, or unknown. A
quantity item shows **Running low** when its count reaches the item's threshold; a level-based item shows it at low or
out.

<Aside type="caution" title="Stock does not reduce itself">
  Bookings and attendance do not automatically consume inventory. Staff must keep counts or levels current, because the
  catalogue is only as current as the latest update.
</Aside>

## Generate a shopping list

Choose a date range in **Shopping list** and select **Generate**. For each matching studio party booking, the Portal:

1. Applies active base-party, food-package, and addition rules.
2. Uses the party's child count for per-child quantities.
3. Totals the required quantity by item.
4. Adds the item's **Keep at least** target.
5. Subtracts the current quantity on hand, never suggesting less than zero.

The result explains the amount needed, stock on hand, minimum target, suggested amount to buy, and which rules produced
the requirement.

<Aside type="note" title="The list is advice, not an order">
  Generating a shopping list does not purchase stock or change inventory. Review its warnings and the physical stock
  before ordering.
</Aside>

## Understand warnings

- **Count first:** the current quantity is unknown, so the system cannot calculate a purchase amount.
- **Party form not completed / invalid child count:** per-child quantities may be missing.
- **No matching or duplicate item:** a usage rule does not map cleanly to one active catalogue item.
- **Qualitative item required:** check its physical level; no numeric purchase amount can be calculated.
- **Unused here or no studio record:** the booking needs an item that is not currently tracked at that studio.
- **No active rules:** the system has no instructions for turning bookings into stock requirements.

## Catalogue and rules

Create catalogue items for consumables only, not reusable equipment. A new item is created for every studio and can then
be marked unused where appropriate. Archived and unused items appear under **Hidden items**; hidden does not mean out of
stock.

Each usage rule must point to the intended catalogue item. Leave rule maintenance to people with the relevant editing
access because changes affect future shopping lists.

If a booking is missing from the list, check its studio, date, party type, food and additions, and child count on
[Bookings](/portal/bookings/) before changing inventory.
